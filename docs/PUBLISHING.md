# Building and publishing WSMarsRoverSim

The production workflow is `.github/workflows/release.yml`. It builds Windows x64,
macOS Apple Silicon / Intel, Linux x64, and the optimized Wasm website.

## Publish a version

Push the commit to `main`, then push a new stable version tag, for example:

```sh
git push origin main
git tag v1.2.0
git push origin v1.2.0
```

Use an unused `vMAJOR.MINOR.PATCH` tag. Major must be 1–255, minor 0–255, and patch
0–65535 for native installer compatibility. Leading zeroes and prerelease suffixes
are not supported. The tagged commit must be in `main`'s history; a push to `main`
alone does not publish a release.

The workflow first builds all nine downloads, then uploads them and `SHA256SUMS`
to a **draft** release. Only after verifying every upload does it publish the release.
This accommodates immutable releases: published assets are never replaced. A rerun
can resume a draft or reuse a complete published release to retry a Pages deployment.
Changes to published files require a **new tag and release**.

Pages is deployed only for the latest release, so publishing an older version does
not roll the website back. Publication runs share a queue; publish one version at a time.
Release notes are generated by the project script and contain download instructions,
without GitHub's automatically appended “Full Changelog” line.

## Downloads

| Platform | Portable, no installation | Optional installer |
| --- | --- | --- |
| Windows · Intel / AMD 64-bit | `windows-x64-WSMarsRoverSim-portable.zip` | `windows-x64-WSMarsRoverSim-installer.msi` |
| macOS · Apple Silicon | `macos-arm64-WSMarsRoverSim-portable.zip` | `macos-arm64-WSMarsRoverSim-installer.dmg` |
| macOS · Intel | `macos-x64-WSMarsRoverSim-portable.zip` | `macos-x64-WSMarsRoverSim-installer.dmg` |
| Linux · Intel / AMD 64-bit | `linux-x64-WSMarsRoverSim-portable.tar.gz` | `linux-x64-WSMarsRoverSim-installer.deb` |

All desktop downloads include Java. Portable packages contain a complete application
folder, not an installer or a single self-contained Windows executable:

- **Windows:** extract the entire ZIP, then open `WSMarsRoverSim/WSMarsRoverSim.exe`.
  Keep the `app` and `runtime` folders beside the executable.
- **macOS:** extract the ZIP, then open `WSMarsRoverSim.app` from that location.
  Moving it to Applications is optional. The ZIP preserves executable permissions,
  symlinks and bundle metadata.
- **Linux:** extract the tar.gz, then run `WSMarsRoverSim/bin/WSMarsRoverSim`.
  The archive preserves Unix permissions and symlinks. Native desktop libraries are
  still required. The optional `.deb` targets Debian/Ubuntu compatible systems.

Packages are unsigned and macOS builds are not notarized. Windows/Linux ARM packages
are not currently built.

`web-wasm-WSMarsRoverSim.zip` contains the complete static website, including the
worker and resources. `SHA256SUMS` covers all nine downloads.

The Wasm toolbar prefers the matching **portable** download via
`https://github.com/OWNER/REPOSITORY/releases/latest/download/ASSET`. The menu also
offers installers and release notes. If a browser conceals the CPU architecture
(common on macOS), the user chooses the platform. Desktop and JS builds do not show
this download control.

## Local builds

The project uses Amazon Corretto JDK 21, including for the Gradle daemon.

```sh
# Optimized Wasm site with the desktop download button.
./gradlew buildOptimizedWasm -PpublishingRepository=OWNER/REPOSITORY

# The same site plus its release ZIP.
./gradlew :webApp:wasmReleaseZip -PpublishingRepository=OWNER/REPOSITORY

# App image and installer for the current OS / CPU.
./gradlew :desktopApp:createDistributable :desktopApp:packageDistributionForCurrentOS -PappVersion=1.2.0

# Archive and stage that platform's two downloads (Python 3; example for macOS ARM64).
DESKTOP_TARGET=macos-arm64 PACKAGE_EXTENSION=dmg python3 .github/scripts/stage_desktop.py
```

Site output: `webApp/build/distributions/wasm`. Web archive:
`webApp/build/distributions/web-wasm-WSMarsRoverSim.zip`. App image and installers:
`desktopApp/build/compose/binaries/main/{app,dmg,msi,deb}`. Staged release files:
`release-assets/`. Native packaging requires the corresponding host OS and CPU;
the workflow uses a separate runner for each platform.

The production Wasm build uses Kotlin, Binaryen and webpack optimizations, ships
the production worker, and omits source maps. Binaryen fast-math is disabled because
the algorithms rely on IEEE infinity/NaN behavior. Without `publishingRepository`,
local Wasm builds hide the desktop download button.

## GitHub configuration

The existing production repository is already configured. For a future copy:

1. Use `main` as the default branch and enable Actions.
2. Select **GitHub Actions** as the Pages deployment source.
3. Allow `v*` tags in the `github-pages` environment's deployment rules.
4. Keep immutable releases enabled.

The build injects `github.repository`; no hard-coded owner, private Git history,
personal access token, or extra secret is needed. The workflow uses `GITHUB_TOKEN`
with write access only in the release and Pages jobs. See GitHub's
[immutable release documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

Renaming the app retains the existing installer identity and supports imports with
the old `WSRoverSim` bundle identifier, including the published seminar-paper data.
